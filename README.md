## Deploying to Cloudflare Pages

The site is pre-built static HTML. There is no build step.

1. Cloudflare dashboard → **Workers & Pages** → **Create** → **Pages** → **Connect to Git**
2. Pick this repository
3. Set:

   | Setting | Value |
   |---|---|
   | Framework preset | **None** |
   | Build command | *(leave empty)* |
   | Build output directory | **`site`** |

4. **Save and Deploy**

Every push to `main` redeploys automatically.

> **Note:** the project record and the internal speaker notes are deliberately not in this
> repository. They exist only as local files (`PROJECT_REPORT.md`, `PROJECT_REPORT.html`,
> `TALKING_POINTS.html`) and are listed in `.gitignore`. This repo is public — keep them out.

## What's in the site

| Path | Page | Who it's for |
|---|---|---|
| `/` | Index — routes visitors by how much time they have | Everyone |
| `/short/` | **8-slide deck.** The send-ahead version, ~4 min | First look |
| `/deck/` | **17-slide deck.** Full detail with sources appendix, ~7 min | The meeting |
| `/proposal/` | Interactive one-page proposal with a revenue simulator | Self-serve reading |
| `/kit/` | Campaign kit — 12 finished graphics and what else is in it | Proof |
| `/kit/playbook/` | Operating playbook: config, six workflow specs, AI brief | Technical review |
| `/kit/emails/` | Eight email sequences plus reply and booking scripts | Technical review |
| `/kit/captions/` | Twelve posts, Instagram and LinkedIn copy written separately | Technical review |
| `/kit/calendar/` | The 28-day execution calendar as a table | Technical review |
| `/files/` | PDFs, CSVs and the raw source text | Downloads |

Both decks are keyboard-driven: **arrow keys** or **space** to advance, **G** for the overview
grid. Phones and touch tablets use a scrolling page with slide taps, previous/next buttons,
and an overview for jumping between slides. The decks print to landscape PDF.

Touch navigation regression checks live in `tests/deck-touch.mjs`. With the site served on
port 4173 and a dedicated Chrome instance exposing remote debugging on port 9222, run
`node tests/deck-touch.mjs`. The suite sends browser touch gestures with smooth scrolling
enabled. See `MOBILE_UI_UX_REPORT.md` for coverage and limitations.

### Rebuilding

`build_site.py` regenerates the stylesheet and the campaign-kit pages from the source
text and CSV files, so edits to the kit flow through to the site:

```bash
python3 build_site.py
```

The decks and the proposal are hand-authored and copied into `site/` as-is.

## Not in this repository

**Internal documents.** The project record and the speaker notes are kept off this repo on
purpose — they discuss pricing reasoning and objection handling that is not for the client's
eyes. They live locally as `PROJECT_REPORT.md`, `PROJECT_REPORT.html` and `TALKING_POINTS.html`,
and are in `.gitignore`.

**Oversized source files.** `About.pdf` (174 MB) and `About.docx` (90 MB) are excluded — GitHub
rejects any file over 100 MB, and both are image-heavy duplicates of
`About me and community.txt`, which is included.
